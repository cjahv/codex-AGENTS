# UI 锐评清单

## 使用方式

- 在需要系统性走查界面时读取本文件。
- 先判生死问题，再谈精修，不要平均用力。

## 一级问题

### 1. 第一眼看什么

- 第一眼是否有唯一焦点。
- 重要内容是否被次要装饰抢戏。
- 主按钮、主标题、主数据是否在同一视觉叙事里。

### 2. 用户怎么扫

- 页面是否存在自然扫描路径。
- 模块是否按任务顺序组织，而不是按实现顺序堆叠。
- 用户是否需要反复左右/上下长距离找对应关系。

### 3. 信息是否压缩得足够好

- 文字是否过多、过散、过重复。
- 能否用图表、图例、标签、状态块、摘要卡替代大段说明。
- 是否把多个低价值提示拆成了多个高噪声模块。

### 4. 视觉是否专业

- 对齐、留白、圆角、边框、阴影是否统一。
- 是否存在“每块都想特别”的问题。
- 是否有模板感、拼贴感、廉价渐变感、伪高级玻璃感。

### 5. 组件是否守纪律

- 相同交互是否复用相同组件语言。
- 按钮、标签、开关、输入框、卡片是否各司其职。
- 是否存在语义混乱的假按钮、假标签、假导航。

### 6. 状态是否一眼可懂

- 默认、悬停、禁用、加载、错误、成功是否区分明确。
- 重要状态变化是否足够显眼。
- 是否过度依赖颜色单通道表达。

## 输出模板

### 总评

- 用一句话下结论。

### 优先级最高的问题

- 问题：指出具体区域和症状。
- 伤害：说明用户为什么会困惑、疲劳、失去信任或误判。
- 修改：给出具体到布局、组件或样式层的动作。

### 精修项

- 只列少量高价值修整项，例如字号级差、按钮样式统一、次级信息收口。

## 典型措辞

- 可以尖锐，但不能空洞。
- 可以说“这块像后台模板默认皮肤”，但要接着说“因为主次不分、卡片样式失控、强调色泛滥”。
- 避免只说“建议优化”“可以考虑”。默认给结论和改法。
